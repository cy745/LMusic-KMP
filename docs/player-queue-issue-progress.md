## #14：多数据源与播放恢复

已落地：

- 数据源独立产生 Snapshot、独立入库；读取能力与扫描状态分开，UI 通过 Repository 获取状态，不直接订阅 MediaSource。
- 播放身份统一为可逆的来源限定 `playbackId`；原始 ID 保留在源内使用。数据库主键、关系、播放动作、歌单及历史引用同步调整，跨源相同原始 ID 不再相互覆盖。
- 历史列表、当前槽位和进度作为一个记录保存；保留列表顺序和重复槽位。数据库已有歌曲立即展示，未就绪歌曲置灰并禁用卡片交互，不等待所有来源后才显示列表。
- Android 恢复列表时同时应用历史 index/position，不再先显示默认列表头；真正打开媒体仍等待所属来源就绪。
- 全局恢复提示倒数 15 秒，可手动关闭。超时只隐藏提示，不取消来源任务、不删除歌曲，也不代表所有后台恢复已经结束。
- 旧查询/进度写入有状态归属检查，同曲重新选择也推进代次；顺序播放到尾停止，列表循环回到开头，随机模式保留新歌位于当前歌曲前面的交互。
- 明确“下一首”请求与普通插入的差异；Android 覆盖手动、自然切换和列表结束入口。
- 失败原因单独持久化；来源未就绪优先置灰，歌曲播放失败显示红色原因并允许重试，成功播放后清除失败记录。失败跳过沿原方向进行且有遍历上限。

- [ ] 封面、模糊背景、歌词重试的完整页面端到端验收；此前 MediaCoverRequest fetcher 异常仍需复核。
- [ ] MediaBrowser、通知栏控制、Room 慢查询/异常的完整交错验证；原生相同队列重新加载和直接 playWhenReady 控制边界。
- [ ] 历史恢复独立清零通知的迟到归属、设置变更与录制之间的一致性进一步审计；不宣称所有进度竞争已消除。
- [ ] “下一首”请求在单项 setMediaItem、批量差量更新中间态下的完整生命周期覆盖。

## #17：外部打开与 Sandbox 文件管理

已落地：

- Android 的 ACTION_VIEW、冷/热启动与 singleTask 入口已接入；优先匹配 MediaStore/已有来源，无法确认时导入 Sandbox，不申请外部写权限。
- Sandbox 公共接口在 commonMain，文件操作抽象在 nonWebMain，Android/iOS 提供平台扩展；SHA-256 在 commonMain。此决定覆盖最初 commonMain 基类方案。
- 内容去重、稳定身份、临时复制、格式校验、持久化索引和原子索引替换已实现；独立 Screen 可浏览、重命名和删除导入文件。
- 外部打开与文件操作按 playbackId 查询目标，结合来源、可用性、路径及提交 revision 确认，接受已经覆盖目标的更高版本，避免错过通知后误超时。
- 外部打开复用已有队列项或插入后播放，不清空原队列。
- 删除先隔离文件，再确认数据库及队列移除，最后删除私有副本；失败恢复文件/索引/快照。回滚队列时校验本次操作仍有效，恢复旧列表/位置但保持暂停，不覆盖用户后续编辑。
- 文件操作与来源启停共用每源操作边界；重命名等待数据库和队列路径刷新。
- iOS 文件入口和 security-scoped access 有代码接入，但不等于 iPhone/iPad 验收完成。

仍需推进（本轮不扩展）：

- [ ] 真实文件系统异常 + Room + MediaBrowser 的整条失败/回滚链路注入。
- [ ] 自动转场/随机重排导致队列已经变化时，当前保守跳过队列回滚；是否需要更精细恢复待评估。“下一首”请求不在回滚记录内。
- [ ] 进程中断、损坏索引/恢复记录、路径冲突的用户可操作恢复方案；原子替换不等于断电 fsync 保证。
- [ ] iPhone/iPad 外部打开、权限生命周期、既有 Documents 文件及播放验证。
- [ ] Desktop 文件关联和具体 Sandbox 实现留作后续，不将平台编译当作运行验收。
