# 曲库与歌曲详情整理（2026-10-27）

最终采用 A 方案：主文字与操作入口加粗，副文字缩小淡化，入口无胶囊背景；歌手按原始署名顺序以小号淡色文字独立跳转。下面按迭代顺序记录；旧截图不代表最终样式。最终实现与 review 结论见 [实施计划](../../architecture/implementation-plan.md#曲库页面与歌曲详情收尾2026-10-27)。

- 共用 LibraryEmptyState：统一首页推荐/最近添加/最近播放、歌曲列表、专辑/歌手列表及详情页的空状态。歌曲列表保留标题，并区分无歌曲与搜索无结果；详情页空列表禁用批量播放按钮。
- 歌曲详情使用媒体库中已拆分的歌手实体，独立标签跳转歌手详情。持续订阅关联数据，标题区的 movableContent 读取最新内容，避免异步资料到达后仍显示旧标题/歌手。
- “下一首播放”调用既有 AddToNext，由播放核心执行正常模式换位和随机模式单个待播意图，不立即跳歌。
- 显式播放按钮：当前歌曲切换播放/暂停并保留进度；其他歌曲选择并播放。普通列表选中当前歌曲的既有规则保持不变。按钮按播放意图显示，等待加载时仍可暂停。
- 收藏 Dynamic Action 定义仍在 lplaylist，由带名称的 Koin 工厂注入；lhome 没有增加对 lplaylist 的编译依赖。来源限定的 playbackId 用于收藏，显示空心/实心状态并支持 toggle。修复首次创建喜欢歌单后漏加第一首的问题。
- 歌手详情的数量随歌曲列表更新，不再停留于初始 0。

验证：首次收藏/取消及不同来源身份隔离测试通过；播放核心相关 12 项测试通过；异步歌手入口及手机宽度空状态 2 项 UI 测试通过。macOS 正式应用实测双歌手拆分、歌手详情跳转、播放/暂停保留进度、收藏与取消、下一首不立即切歌、无搜索结果及清除搜索。该阶段完成 Android 编译；后续已多轮 Release 保留数据覆盖安装真机，最终交付见文末及实施计划。

## Android Release 详情页闪退修复

真机异常 `No instrumentation registered` 的起点是 Compose `DefaultAndroidResourceReader`。读取缺失图标时，资源库回退尝试测试环境资源，因正式应用没有 instrumentation 而抛错；这不是需要给正式应用注册测试环境。

旧 APK 检查确认缺少 `media_play_fill.xml` 和 `media_pause_fill.xml`。自定义 `cmpshrink` 在合并资源后直接删除未引用图标，但 Kotlin 中新增图标引用不会使原有 `mergeReleaseAssets` 失效，导致复用已裁剪的旧产物。

现在仅对启用裁剪的变体强制完整执行资源合并、禁止复用该任务的构建缓存，保留 AGP 所需的 InputChanges 跟踪。代价是 Release 打包每次重新合并/扫描这部分资源，不影响运行性能和应用数据。新增 `scripts/verify-compose-icons.py` 校验最终 APK 是否包含代码引用的图标；安装验收前运行此检查。

验证结果：旧 APK 检出上述两个缺失图标；修复版 `assembleRelease` 成功，APK 的 42 个源码引用图标全部存在。额外临时增加 `RemixIcon.Media.pauseMiniFill` 引用后，仅运行 `mergeReleaseAssets` 即成功恢复原先被裁剪的图标；移除临时引用再次合并，恢复为 42 个，临时文件已清理。修复版通过 `adb install -r` 覆盖安装成功；使用正式 Deep Link 进入歌曲详情后进程保持运行，未新增该进程的 crash buffer 记录。保留手机应用数据。

## Smart Bar 按钮修正

- 收藏保持矩形，与其他操作一致；已收藏使用“我喜欢”歌单的红心色 `#FF3C3C`。
- 歌曲详情的下一首、播放/暂停均使用 Dynamic Action；动作列表按歌曲身份记忆，播放状态仅在动态内容内部订阅，避免播放/暂停切换触发整组动作替换和过渡。
- 紧凑 Smart Bar 仅显示图标，更多弹窗显示图标和文字；播放按钮仍按播放意图显示，加载中也能表达暂停操作。
- 修复 Static Action 未指定颜色时图标直接使用 `Color.Unspecified` 的问题，改用已经解析的主题前景色。
- 新增 UI 回归用例覆盖紧凑/展开显示、播放/暂停状态更新及动作列表实例保持不变。上方旧详情截图记录的是此前版本，收藏形状及操作文字以本节修正为准。

本轮验证：`SongDetailActionsTest` 通过；`assembleRelease` 成功；最终 APK 42 个源码引用图标全部存在。已保留数据覆盖安装到 Android 真机，正式 Deep Link 启动详情后进程保持运行。真机视觉手感仍由用户体验确认。

## 区分下一首播放与添加歌单

歌曲详情操作从左到右调整为：**下一首播放（文字）→ 添加到歌单（原列表加号图标）→ 播放/暂停 → 喜欢**。下一首继续使用播放核心的 AddToNext 规则；列表加号改为进入既有歌单选择页，由用户选择目标歌单后确认添加。单曲添加歌单动作由 lplaylist 通过 Koin 暴露，传递来源限定的 mediaId，不给 lhome 引入歌单模块依赖。添加歌单在 Smart Bar 只显示图标，在更多弹窗显示图标与文字。

验证：更新后的详情动作 UI 回归测试通过，Release 构建通过，42 个图标资源校验通过；Koin 生成代码确认单曲歌单动作按 mediaId 参数注册。新版 Release 已保留数据覆盖安装至 Android 真机。

## 下一首播放方向图标

为减少 Smart Bar 宽度，最左侧“下一首播放”恢复为 Dynamic Action 图标：随机模式使用 RemixIcon.Editor.insertRowTop，其他模式使用 insertRowBottom，对应随机模式待播放项在当前歌曲上方、正常模式在下方的显示规则。模式观察在按钮内部进行，不替换动作列表。更多菜单仍显示“下一首播放”文字；添加到歌单、播放/暂停、喜欢的顺序与行为保持不变。

验证：模式切换和播放状态变化时动作实例保持稳定的 UI 回归通过；Release 构建通过；最终 APK 的 44 个引用图标（含上下插入图标）检查通过。已保留数据覆盖安装至 Android 真机。

## A 方案落地

采用用户确认的轻量文字空状态：去掉音乐图标底块、左对齐标题与说明。歌曲列表保持与 NavigatorHeader 相同的 20dp 水平边距，空提示顶部 56dp 加上标题区底部 16dp，共约 72dp 留白。空库提供“添加媒体源”入口，搜索无结果提供“清除搜索”并调用原有 SearchFor 事件；首页最近添加空区同样提供媒体源入口。共用空状态组件让其他库列表和分区沿用轻量文字样式。

歌曲详情的每位歌手使用独立可点击的淡色文字，无边框或箭头，使用主题文字色 65% 不透明度适应不同主题；悬停/按下提亮，至少 44dp 点击高度，保留传入 artistId 和歌手实体的详情跳转。

验证结果：LibraryPresentationTest 三项测试通过，实际覆盖异步歌手独立点击节点、空库显示及两种空状态回调区分。手机宽度 Compose 渲染图已更新并检查（非真机截图）。Release 构建成功，45 个引用图标资源校验通过。已保留数据覆盖安装 Android 真机并启动歌曲详情页。
