# 播放页队列滑动与元素动画（2026-10-28）

## 验收状态

用户已在 Android 真机确认：左右滑动可用、横纵手势不冲突、设置下一首不拉回顶部、点击切歌封面不闪烁且元素动画正常。标题和封面更新链路经代码核对继续有效，保留 key 不会禁止内容重组。

## 最终行为

- 左滑：沿用 QueueAction.AddToNext → Playback.playNext。顺序/列表循环/单曲循环把歌曲移到当前歌曲之后；随机模式替换唯一待播放意图。不会立即切歌或恢复暂停；当前歌曲设为下一首仍忽略。
- 右滑：仅移出播放队列，不删除曲库文件。删除当前歌曲后的选曲与播放意图交给现有核心处理。随机模式中，队列外的待播放歌曲也能移除并清除意图。
- 松手且位移达到 min(96dp, 行宽×30%) 才执行一次动作。短滑、取消、多指介入不触发；未达阈值时以 180ms 回弹。保留点击播放、长按详情与无障碍动作。
- 越过系统触摸 slop 后确定主方向：纵向交给列表和嵌套滚动；横向锁定后在 Initial 阶段消费后续移动及释放，包括纯纵向偏移。监听容器固定，仅卡片随手指移动。
- 左滑设置下一首时当前歌曲不变，保持浏览位置。不能把保留的 currentPickedByUser 标记误当作新一次点击。
- 点击另一首播放时，前段原生渐隐、后段原生上移。明确点击最后一行也保留被点行 key；上一首操作仍保留默认反向差分行为。

## 实现边界

SwipeableQueueItem 只处理手势和展示，队列策略复用现有核心。随机待播放行用歌曲身份作为 key，替换待播放歌曲会取消旧行手势。来源暂不可用的歌曲仍可移出队列。

PlaylistScrollPlan 区分当前歌曲未变与真正切歌。PlaylistItemTransition 在队首不可见、选中行可见时，先只从 UI 临时列表移去不可见前缀，依靠稳定 key 自动重定位可见行，保持其位置和封面组合；等待实际布局应用后，再提交完整差分队列，在相同滚动坐标请求回顶，以保留 animateItem 的淡出图层与位移动画。这里只改变 UI 显示列表，不改播放核心队列。

首行部分裁切时，用正常滚动露出剩余部分；滚动在子协程中执行，用户中断不会终止队列观察。布局等待计入独立更新的随机待播放行，避免期间新增意图导致队列刷新停住。

标题、副标题、可用性及 extra 内容变化会保留 key 并更新行内容；封面通过数据源内容代次触发新请求，加载期间保留旧图，新图就绪后渐变替换。没有封面变化通知时不会凭空刷新外部文件。

## 实现取舍

已移除先清空列表一帧的 RebuildAtTop，以及随后尝试的整表平移、220ms tween、低刚度 spring 补偿。scrollToItem 改变坐标会重置原生元素动画，准备阶段即使视觉等效的跳转也会释放离场图层；最终方案通过稳定 key 重定位，避免这些操作。验证不能只检查最终位置，还必须检查中间帧和渐隐像素。
