# 共享封面过渡统一修复（2026-10-28）

## 问题与统一处理

用户反馈首页每日推荐、最近添加首次进入详情时共享封面闪烁。全项目扫描共享元素及缓存交接入口后，统一处理以下问题：

| 入口 / 组件 | 原问题 | 最终处理 |
| --- | --- | --- |
| 每日推荐 | 缓存 key 传空；歌曲、专辑、歌手全部进入歌曲详情 | 传递实际图片加载结果；按类型进入对应详情并携带数据快照 |
| 最近添加、最近播放、歌曲列表、搜索、专辑/歌手/歌单中的歌曲 | 重新推算缓存 key，可能与当前封面的版本、附加参数不同 | 从源组件的成功加载结果交接完整 MemoryCache.Key |
| 播放队列 | 将 Item 包装对象用于计算封面 key | SongCard 直接交接真实加载结果，不再推算 |
| 专辑、歌手和歌曲详情头图 | 依赖可为空/不准确的字符串 placeholder key，首次大图加载有空档 | 统一 SharedCoverImage，从共享信息还原完整占位 key；等待期间保留图像 |
| 歌曲详情 → 所属专辑 | 复用歌曲的共享标识，缺少专辑卡片自身的 COVER 元素 | 专辑卡片独立共享标识、实际封面与缓存交接 |
| 重复出现的歌曲/专辑/歌手卡片 | 仅业务 ID 构造共享标识，多个位置可能碰撞 | rememberSharedMap 加入组合位置标识，跳转仍传递实际源标识 |
| 部分专辑/歌手卡片 | 无 key 的 remember 固定旧模型、标题或图片请求 | 随模型与相关文本变化更新；推荐分组使用类型和稳定 ID 而非标题标识 |
| 原始 LAudio 图片请求 | 只使用来源代次，遗漏单曲代次 | 与 MediaCoverRequest 一样使用 forItem(id).generation |

## 实现

SharedContextScope 保存当前组件实际显示封面的缓存 key；点击时将 key 字符串及 extras 编入现有 SharedMap。目标页从同一份共享信息恢复 MemoryCache.Key，作为 Coil 占位请求。只传递字符串元数据，不传 bitmap、不另建全局图片缓存。成功加载结果会更新交接信息，失败或等待不会伪造新图已就绪。

SharedCoverImage 统一图片加载：共享转场期间不叠加 Coil crossfade；后续封面版本改变时，等待或失败期间保留当前已加载 painter，新图成功后更新。SongCard 保留原有封面 AnimatedContent 手感，并通过同一交接对象记录真实成功结果。

已删除 retrieveCacheKey 推算工具、各路由 coverCacheKey 字符串参数及重复请求构建。详情页继续接受原有实体快照，避免首次只传 ID 时空数据起步。推荐封面的重复点击区域禁用 ripple，避免按压覆盖层随共享图像进入转场。

歌手列表原本仅共享文字，仍保留该设计；图片缓存交接不等于为它增加封面几何过渡。没有源图片加载成功或对应 Coil 内存缓存已逐出时，仍正常加载图片，不保证凭空存在占位图。

- 放行大图后触发下一次封面更新，验证等待期间保留当前大图而非退回源缩略图，新图完成后正常显示。
- 首页最近添加跨来源相同原始 ID 回归，以及已有播放队列手势/原生动画回归。
- 17 项回归零失败（缓存交接 2、首页/详情 7、队列交互 8）。共享转场最初五帧逐一检查通过；Desktop JVM 与 iOS Simulator 全应用编译通过，Android Release 构建成功（5m46s），45 个图标检查通过。

## 歌曲详情首帧布局补充（2026-10-28）

用户确认封面闪烁消失后，发现进入歌曲详情时专辑区突然出现，导致下面内容跳动。原因是歌曲快照已存在，但专辑/歌手订阅初始为空：专辑卡片随后插入，歌手文本随后变成带最小点击高度的链接行。

详情页现在直接使用歌曲元数据生成首帧专辑和歌手，ID、专辑名称规范化与曲库组装规则一致。仓库数据到达后更新相同元素，不延迟转场，不用定时器遮掩布局变化；真实元数据更新仍可正常生效。只传歌曲 ID 而没有快照的入口仍需等待歌曲查询，这种入口不承诺凭空显示元数据。

新增 UI 回归：仓库尚未返回时专辑已显示、歌手已可点击；返回等价实体后，专辑和歌手位置尺寸完全一致；后续专辑标题改变正常显示。

本轮验证完成：lhome JVM 共 8 项测试通过，Android Release 构建通过（3m10s），45 个图标校验通过；Android 真机保留数据覆盖安装返回 Success。待用户确认实际转场观感。
