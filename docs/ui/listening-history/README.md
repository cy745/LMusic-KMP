## 已确认的统计口径

- 用户主动播放、切歌时立即进入最近播放，包括加载期间；静默恢复队列和后台预加载不记历史。实际播放失败时保留这次用户选择，但不计播放次数。
- 收听时长只累计播放核心处于 Playing 的实际经过时间；暂停、缓冲、定位等待不计入，也不使用进度跳变量推算时长。
- 实际开始播放立即计一次，不再设 30 秒门槛。暂停/缓冲/定位后恢复不重复计次。
- 暂停再恢复仍属同次；切走后重新选中、自然循环新一轮属于新次。点击当前选中歌曲不重启、不额外计次；元数据刷新不产生新次。
- 四张统计卡片：今日收听、本周收听、本周播放次数、本周不同歌曲数。后三项可切换本月。
- 历史列表按日期分组，并提供日期范围筛选。

## 记录修复实现

1. PlaybackCore 在每条命令或运行时事件处理完成后发出有序观察，避免 StateFlow 合并以及中间队列状态导致漏记/误记；自然结束单独发出一次完成信号。
2. Android、iOS、桌面与 Web 共用 observeCore → PlaybackDataTracker → ListeningRecorder；移除 Android 的旧 Media3 历史监听，iOS/Web 补齐注入。
3. 记录器以单调时钟计时，事件携带接收时间进入串行队列。主动选曲立即写入最近播放，实际发声后计次，播放期间每 5 秒持久化，暂停、切歌、结束立即保存；失败的写入保留待重试，不影响播放。
4. m_history 增加独立 playCount，history_day 按本地日期分配真实时长，跨午夜分段，播放次数只归实际开始的那一天。按来源限定的歌曲标识去重统计。
5. 数据库 5→6 保留全部旧历史；旧数据仅能从已记录时长恢复至少一次的有效计次，不推测旧逐日统计。新的每日统计从本次修复起积累。
6. 最近播放查询过滤旧的负时长预保存行，歌曲加载范围限制为最新 6 首；播放次数不再把全部历史行直接当成有效播放。

## 第三轮：页面生命周期根因（2026-10-27，已修复并安装）

用户反馈只有第一首及部分后续歌曲显示、清除仍无效果。真机只读服务诊断确认清除已执行（operation=cleared、rows=0、days=0），页面却保留旧记录。

定位到 HistoryVM 同时使用 @Single 全局单例与 koinViewModel 页面生命周期管理。历史页返回后页面 ViewModelStore 销毁，取消全局单例的 viewModelScope；再次进入或首页最近播放复用已销毁实例，statistics/stateIn、pager/cachedIn 与 historyState 的收集永久停止。清除走独立的记录器，因此依然能执行并提示成功，而页面不再刷新。

模拟器使用原包完成复现：进入历史页 → 左下返回 → 再进入 → 长按清除；数据库 rows=0、days=0，页面仍有 1 次/1 首及 Astronomy 行，成功提示也可见。此前仅停留页面内验证不足以覆盖此问题。

修复：HistoryVM 改为 @KoinViewModel，与其他页面一致，按 ViewModelStore 创建实例；历史仓库和记录器保持应用级单例。新增测试检查实际 KSP 生成的注册不再是单例。待新 Release 完成相同进出页面路径验证及保留数据安装。
