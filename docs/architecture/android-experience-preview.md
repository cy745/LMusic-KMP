# Android 首轮真机体验版

本轮优先让用户尽早在自己的 Android 手机上实际听歌，不等待其他平台的缓存、连续输出或高级音效全部完成。正式播放入口已经使用方案 B 的共享核心，不需要进入调试原型页面。

## 本轮收敛

- 点歌和替换队列时，把开始播放意图放进同一次标准 MediaSession 队列请求。服务取出后立即清除一次性标记，核心原子处理；不会先准备失败、再被迟到的 Play 重试一次。保留 MediaSession 的大列表传输方式，没有另建自定义整队列 Bundle 协议。
- 替换队列且保留当前歌曲时，保留进度和播放/暂停意图；未指定起点且当前歌曲不在新队列中时选第一首。删除当前末项则回到第一首。
- 点击已选中歌曲不重新开始、不恢复播放；暂停后继续切歌保持暂停。
- 加载/缓冲当前歌曲时，标题区显示一个小型等待指示，不改变标题/歌词的短过渡，也不根据预加载下一首的状态显示假等待。等待期间仍可暂停或切歌。
- 共享适配的手动上一首/下一首可用性与首尾相接规则一致。

## 可体验范围

本地及现有在线来源、播放队列与随机下一首、进度和歌词联动、暂停/切歌短音量过渡、Android 预加载与已验证的自然无缝衔接、系统媒体控制、后台与锁屏播放、已有通用缓存路径。

默认体验输出仍为 48 kHz PCM。请求原样输出会明确显示未生效原因并保持正常播放；没有实现独占 DAC、Android SRC 旁路、杜比或空间音频生效验证。交叉淡化关闭且未实现。

## 验证与门槛

- JVM：共享核心 30、缓存 17、播放页/歌词/历史等 63、共享适配 9、Android 队列桥接 9 项，共 128 项通过。
- Android 模拟器：21 项通过。正式会话场景扩展了实际应用点歌、队列替换、删除末项、同曲点击、退到桌面后继续播放、熄屏后继续播放及系统控制暂停；另有一项瞬时失败的原子选曲验证。原 P3 无缝 PCM 测量与缓存离线读取回归保留。
- 公共接口变更后，iOS Simulator 和 Wasm 编译检查通过。本轮不新增其他端实播能力声明。
- 安装包是正式应用入口的 debug 体验包；不是仅能播放合成音频的演示原型。

这是**首轮真机体验门槛**，不是所有场景的正式发布验收。模拟器无法证明蓝牙/耳机/USB DAC 实际切换、厂商后台限制和主观听感。后续专项已验证完整应用杀进程后，从缓存恢复歌曲、队列、暂停进度并离线播放，以及缓存缺失时的错误与重试行为；测试以合成音频直接填充通用缓存，未覆盖真实服务端认证及网络反复恢复。大库和长时间运行仍需专项验证，详见实施记录末尾。

## 安装方式与数据保留

交付包位于仓库 `build/experience/LMusic-plan-b-preview-20261026.apk`，同目录提供 SHA-256。当前包约 52 MiB，包含 arm64-v8a、armeabi-v7a、x86、x86_64。安装包应用 ID 为 `com.lalilu.lmusic.kmp`。

优先覆盖安装，保留已有数据。如果手机上已有版本签名不同，Android 会拒绝覆盖；此时不要为了安装直接卸载旧版，需要先确定保留原数据的安装方式。首轮包随后已按用户请求覆盖安装到连接的 Android 真机，安装成功且未清除数据。后续冷启动专项仅操作模拟器，手机保持该体验版本。

## 第一轮体验建议

按自己的日常方式使用即可，尤其留意：

1. 连续切歌、加载时暂停，是否只播放最后选择的歌曲。
2. 自然衔接和单曲循环是否有可感知的空隙、爆音；手动切歌是否及时。
3. 锁屏、切后台、其他应用发声、拔耳机后，播放行为是否符合设置。
4. 拖动进度时歌词是否跟手，暂停后是否发生意外恢复。
5. 听过并完整缓存的歌曲，在网络不可用时的实际体验。

如果出现问题，记录歌曲来源/格式、操作步骤及是否使用蓝牙或 USB DAC，比单独描述“卡了一下”更容易定位。不需要为了测试修改个人媒体库。
