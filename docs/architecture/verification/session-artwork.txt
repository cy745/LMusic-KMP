Android media notification artwork — 2026-10-26

Root cause:
- MNotificationProvider submitted MediaItem to Coil; no MediaItem mapper/fetcher exists.
- Session metadata contained neither artworkData nor artworkUri. Android system media UI
  could therefore not obtain artwork even if a notification-only loader were repaired.

Implementation:
- MService binds current selection + per-song content generation to the existing
  MediaCoverRequest pipeline. Decode/PNG encode off main thread, exact 256px request.
- Repository lookup waits for the selected row, and selection/content changes cancel
  stale work. CoreSessionPlayer checks selected identity before publishing the bytes.
- Artwork is presentation metadata only. No queue replacement or audio preparation.
- Legacy notification reuses the bounded session bitmap on every rebuild; no stale
  asynchronous notification builder can overwrite newer controls/artwork.
