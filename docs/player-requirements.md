# 跨端播放器需求确认记录

更新日期：2026-10-26。

本文记录用户在重构前讨论中明确确认的目标行为，不代表现有实现，也不是已确定的技术方案。后续架构评估以这些行为为依据；旧文档与现有代码不能自动成为需要保留的需求。页面点击规则仍待逐页讨论。

## 目标和讨论方式

- 目标是满足体验、精简高效且高度可维护的跨端播放器，允许平台能力差异。
- 不以时间或 Token 成本限制方案探索，允许先跑通架构，再逐步完善能力。
- 期望能力包括无缝播放、提前预加载、淡入淡出、交叉淡化、AI 分析衔接策略、Hi-Res、Android 绕过 SRC、杜比与空间音频；具体优先级、平台支持和技术选型未定。
- 先澄清效果，再评估现有架构，最后制定重构方案；当前不实施重构。
- 当前阶段暂不考虑交叉淡化及 AI 智能衔接，先做好其他基础能力，再重新讨论交叉过渡。不得为了暂缓的交叉功能给当前方案加入双路混音状态或相关验收要求；无缝播放与下一首预准备仍保留。
- 后续按相关主题批量确认，每轮更新本记录。未回答的问题保持待定，不以建议代替确认。

## 播放意图和加载

- 选曲、播放意图与准备状态分别表达。
- 正在播放时手动切歌：立即更新选曲，旧歌短渐出后停止；新歌就绪后短渐入播放。
- 新歌未就绪时保持安静并显示加载状态，不继续播放旧歌。
- 等待期间允许继续切歌或暂停。
- 暂停只取消自动播放意图，允许后台继续加载和预准备；就绪后保持暂停。
- 已暂停时，上一首、下一首或直接点选其他歌曲都保持暂停，只更新选曲并准备。
- 快速连续切歌立即推进选曲，只需播放最终停留的歌曲；中间歌曲无需逐首发声，淡化不能阻塞后续操作。
- 旧选曲的迟到加载结果不能接管新选曲。
- 点击当前已选中的歌曲：不重启、不改变进度、不改变播放或暂停状态。
- 自然播完但下一首尚未就绪：安静等待并显示加载状态，就绪后自动播放；不重播旧歌，不因加载慢跳过；期间暂停和切歌仍生效。

## 音频过渡

- 默认优先播放体验。播放或恢复采用短渐入，暂停采用短渐出后暂停。
- 手动切歌采用短渐出和短渐入，不能有明显操作延迟；后续提供开关，默认开启。
- 自然歌曲衔接无缝，不做淡入淡出；无缝播放与交叉淡化是不同功能。
- 交叉淡化暂缓，后续重新讨论；此前默认关闭的设想留档，不作为当前交付要求。
- 原样输出模式由用户主动开启；Hi-Res 支持不等于必须开启原样输出模式。
- 精确淡化时长、曲线、原样输出与处理功能的冲突策略待定。

## 队列身份和编辑

- 实际队列按来源与歌曲 ID 唯一去重；同一来源同一首歌最多一项，不同来源即使同名也保留。
- 普通模式按实际队列从上往下播放；UI 将当前歌曲旋转到第一位显示。例如内部 `[A,B,C,D]` 当前 C，UI 为 `[C,D,A,B]`。这个显示变换属于 UI；Playback 记录完整队列与当前位置。
- 手动排序保持当前歌曲身份、进度、播放或暂停意图不变，只改变队列及索引；随机模式清除待播放意图。
- 删除当前歌曲：选中实际队列中的后一首；删除最后一首则回到第一首；保留播放或暂停意图。删空则停止。
- 替换队列且未指定起始歌曲：包含当前歌曲则保留歌曲、进度与播放意图；不包含则选第一首、从头准备、保留播放意图；空队列则停止。
- 替换队列在随机模式下清除待播放意图。
- 空队列添加歌曲：选第一首，保持暂停，允许预准备；必须明确执行播放才发声，不继承清空前的播放意图。

## 普通模式和下一首播放

| 模式 | 自然结束 | 手动上一首或下一首 |
| --- | --- | --- |
| 顺序播放 | 按队列继续，最后一首结束后停止 | 按队列切换，首尾相接 |
| 列表循环 | 按队列继续，末尾无缝回到第一首 | 按队列切换，首尾相接 |
| 单曲循环 | 无缝重复当前歌曲 | 按队列切换，首尾相接 |

- 手动切换保持原播放意图；正在播放时使用短淡化，暂停时不发声。
- 顺序模式末尾自然停止后仍选中最后一首；再次播放从该歌曲开头开始，不回到第一首。
- 普通模式的“下一首播放”直接移动已有歌曲或插入新歌曲到当前歌曲后面，不维护独立插播请求列表。
- 示例：`[A,B,C,D]` 当前 A，指定 D 后为 `[A,D,B,C]`；再指定 C 后为 `[A,C,D,B]`。修改后的顺序持续有效，后续循环沿用。
- 重复指定同一歌曲只移动到最优先的位置，不新增副本。
- 单曲循环下指定 D 下一首只调整队列；自然结束仍循环当前歌曲，手动下一首才播放 D，随后自然结束循环 D。
- 所有模式中，把当前歌曲设为下一首均直接忽略，不移动、不重复添加、不重启。

## 随机模式

- 下一首方向向上，上一首方向向下；新歌曲成为当前歌曲后，原歌曲显示在其下面。
- 这种随机选曲与队列换位属于实际 Playback 行为，不只是 UI 变换；UI 负责呈现。
- 进入随机模式保留当前歌曲、进度、播放或暂停状态，不因切模式打断播放。允许后台提前选取并预加载随机候选，但到下一首操作或自然结束实际切歌时才改变实际队列和 UI，不提前换位。此规则替代此前“到切歌时才随机选曲”的约定。
- 退出随机模式保留已经调整过的实际队列，不恢复原顺序；当前歌曲、进度及播放意图不变，之后按普通顺序继续；清除待播放意图。
- 允许重复，排除当前歌曲并避开最近播放的若干首；小队列缩小近期排除范围。不要求整轮不重复。具体近期数量待定。
- 最近播放只记录真正开始播放的歌曲，快速切过但未发声的中间歌曲不计入。
- 上一首用于回听刚听过的歌曲；回退后点下一首仍重新随机，不沿历史向前返回。
- 示例：A → B → C，上一首到 B，再下一首重新随机；候选足够时避开近期的 C。
- 仅一首歌曲时，手动下一首从头播放并短淡化；自然结束无缝重复。明确失败仍停止，不能无限重试。

### 随机模式的待播放意图

- 始终最多一个；用户指定的歌曲优先于随机选择。
- 在当前歌曲上方显示待播放元素；再指定另一首直接替换，不累积多首。
- 这是对普通模式移动队列规则的明确例外，不采用“C 播完再播先前指定的 B”的请求栈。
- 指定 C 成功开始播放后清除意图；C 成为当前歌曲，原歌曲 A 显示在其下面；之后恢复随机。
- 指定 C 加载失败也清除意图。有播放意图时随机尝试其他歌曲，遵守本轮失败去重；已暂停则停留 C 显示错误。
- 用户主动点其他歌曲、手动上一首、替换列表、增删歌曲、手动排序、退出随机模式均清除意图。
- 标题或封面刷新、UI 显示重排、随机规则内部换位不清除意图。
- 把当前歌曲指定为下一首是无操作，不影响已有其他待播放意图。
- 点击当前已选中的歌曲、执行播放或暂停，都不清除已有待播放意图。
- 下一首操作或自然结束使用待播放意图；暂停不会使准备好的歌曲自行发声。

## 失败与主动重试

- 尚在加载不等于失败；具体超时与失败判定待定。
- 除单曲循环外，明确加载或播放失败且仍有播放意图时，默认自动尝试其他歌曲；遵循下面的方向与边界规则。
- 单曲循环是例外：加载或播放失败后直接暂停，停留当前歌曲并显示错误，不自动切下一首，即使自动跳过设置开启也不跳过。
- 手动上一首切换失败时沿上一首方向继续寻找；手动下一首沿下一首方向寻找，不突然反向。随机模式的向前推进仍按随机选曲规则。
- 顺序模式自然推进时，后续歌曲全部失败则到末尾停止，不跨回开头；手动切歌触发的失败遍历允许首尾相接。单曲循环仍优先遵循失败即暂停的例外。
- 后续提供开关，允许失败后停留当前歌曲、显示错误、等待操作。
- 用户已暂停时，失败只停留当前歌曲并显示错误，不自动切歌或恢复播放。
- 一轮连续失败中每首歌最多尝试一次；全部候选失败后停止并显示错误，等待主动重试。
- 成功开始播放后结束本轮失败记录；正常随机允许重复与失败轮次去重是两套不同规则。
- 失败停止后点击播放：先重试当前选中的歌曲，开启新一轮失败记录；再次失败按自动跳过设置、当前模式和方向边界处理，单曲循环仍直接暂停。

## 重启恢复

- 重启应用恢复实际队列顺序、当前歌曲、进度和播放模式，但默认保持暂停，不自动发声。
- 随机待播放意图只在当前会话有效，重启后不恢复。
- 启动时来源暂未就绪，仍展示恢复的队列与当前歌曲，不因暂时无法解析而删除记录或改选；明确播放后再按加载和失败规则处理。
- 恢复过程中用户主动选曲或编辑队列，以用户新操作为准，迟到的恢复结果不能覆盖它。

## 外部设备与系统中断

- 以当前 Android 实现为参考，完善多端支持并统一业务行为；平台限制通过适配层表达，不视为各端已实现。
- 保留“监听耳机拔出”开关，默认开启。开启时，有线耳机、蓝牙耳机或 USB DAC 断开导致暂停，保留歌曲和进度，不自动转到扬声器继续发声；加载期间断开也取消自动播放意图。重新连接不自动恢复。
- 关闭该开关时，不因设备断开主动暂停，保持播放意图并在可用输出上继续播放；这不覆盖系统强制中断或输出不可用的限制。
- 来电等临时系统中断时暂停；中断结束且系统允许时，仅当中断前有播放意图、期间未主动暂停或更改选曲且输出仍适合恢复时自动恢复。用户操作优先。
- 其他应用长期接管音频播放时暂停，不自行抢回；用户明确点击播放才重新申请播放。
- 短暂提示或导航播报要求压低音量时，默认降低音量并继续播放，结束后恢复；具体音频路径不支持时的降级策略另行确定。
- 锁屏、通知栏、耳机和车载的播放、暂停、上一首、下一首遵循与应用内相同的业务规则；系统强制中断无需等待淡化完成。
- 当前代码参考：`lplayer/src/commonMain/kotlin/com/lalilu/lplayer/LPlayerKV.kt` 中 `handleBecomeNoisy` 和 `handleAudioFocus` 默认均为 true；`lplayer/src/androidMain/kotlin/com/lalilu/lplayer/service/MService.kt` 在构建 ExoPlayer 时应用设置，并监听设置变化动态更新。音频焦点开关的跨端具体语义仍需结合平台核验，不因此宣称上述所有细节均已被现实现覆盖。

## 进度定位与歌词联动

- 拖动进度条时展示目标位置，并联动歌词滚动预览；松手才提交定位，避免拖动中反复加载。
- 定位保留播放或暂停意图；目标位置未就绪时安静等待并显示加载状态，就绪后按最新意图处理。
- 连续定位以最后一次为准；切歌使旧歌曲的定位结果失效，定位不能阻塞暂停或切歌。
- 时长未知或来源明确不支持定位时禁用拖动，不显示虚假的定位成功。
- 定位超出范围时限制在有效时长内；主动定位到末尾不自动切歌，停留当前歌曲并停止发声，之后点击播放从头开始。
- 重构前必须理解近期进度条与歌词提交，不能把复杂交互简化成一个直接绑定引擎位置的滑块。
- 拖动预览期间，原本正在播放的音频仍按原位置继续播放，原本暂停则保持暂停；只有正常松手才真正定位。取消拖动则不定位，进度条与歌词一起平滑回到实际进度。
- 松手后若定位尚未完成，进度条与歌词停留目标位置并显示加载状态，不按旧播放状态虚假前进，也不因固定短超时回弹；定位完成后再跟随真实进度。
- 点击歌词行采用与进度条相同的定位规则，包括保留暂停意图、最新请求优先与定位等待反馈。
- 保留现有进度条与歌词联动手感，但允许重构具体实现；旧的超时猜测和补偿逻辑不是保留要求。视觉平滑效果与猜测引擎完成状态的补偿机制应区分。

## 预加载与网络等待

- 当前歌曲播放或定位所需的数据优先于下一首预加载；预加载不能让当前播放卡顿，资源紧张时优先减少或停止预加载。
- 下一首后台预加载失败不打断当前歌曲，不立即自动切歌，也不计入当前播放的连续失败轮次；实际选中该歌曲时再执行正式加载与失败规则。
- 网络暂时中断或缓冲耗尽时保持当前歌曲和播放意图，安静显示缓冲状态；恢复后按最新意图继续。有限重试或无进展超时后才认定失败，具体阈值待定。
- 随机模式允许提前选取并预加载一个候选，但不提前改变实际队列或 UI，也不改变当前播放。用户明确指定下一首时，该指定优先于后台随机候选并替换预加载目标。
- 后台随机候选与用户明确指定的待播放意图是不同概念；提前准备候选不等于在 UI 上创建一个用户指定的待播放元素。
- 默认只为一个下一首目标做播放预准备，不同时解码多首候选；提前准备的时机和缓冲量按网络、格式和设备调整。
- 默认允许移动网络上的下一首预加载，提供“仅 Wi-Fi 预加载”和“关闭下一首预加载”设置；这些设置不阻止用户主动选择歌曲后的正常加载。
- 暂停后允许完成当前歌曲的必要预准备，但不无限下载；下一首预加载暂停新增工作，已缓存数据保留，解码资源可按内存压力释放，恢复播放后再继续预加载。
- 队列编辑、模式切换或新选曲使候选失效时，取消过时的预加载和预准备；已下载且仍有效的缓存可以复用，迟到结果不能改变选曲或开始发声。
- 播放缓存与用户明确下载分开：前者受容量限制并自动淘汰，后者按离线下载规则管理，不因播放缓存清理而删除。
- 具体预加载时机、缓冲量和缓存容量留到实现时通过验证调整，不在需求讨论阶段锁定数值。

## 原样输出与体验模式

- 原样输出模式启用时，暂时停用应用内会修改采样的处理，包括音量淡化、交叉淡化、EQ、响度归一化及应用内空间化；保留原设置，退出该模式后恢复。此项是默认操作淡化规则的例外，不代表应用一定能关闭设备自身的处理。
- 当前歌曲或输出设备不支持原样输出时，默认回退到兼容路径继续播放，并明确显示“原样输出未生效”及可知原因；不支持时优先保证正常播放，不静默宣称成功。
- 默认体验模式下，不同歌曲格式切换优先保持连续播放，允许必要的高质量格式转换；原样输出模式优先保持原格式，必要时允许输出重建造成短暂间隔，不承诺所有格式之间都无缝。
- 音频信息分别展示源文件格式与实际可确认的输出格式；无法确认系统后续处理时显示未知，不仅凭源文件或请求参数标注 bit-perfect。用户开启了该设置不等于实际生效。
- 原样输出路径无法按系统要求压低音量时，采用暂停代替应用内修改采样；中断结束按已确认的恢复条件处理，不擅自切换处理模式。
- 原样输出具体支持范围、状态验证方式与平台限制留到技术验证；兼容回退后音效设置如何恢复仍待明确。

## 暂缓的交叉淡化与智能衔接

本节保留此前讨论结果，已被最新阶段决定暂缓，不作为当前实现或验收要求。先完成其他基础能力，再重新评估交叉过渡；这取代此前“先稳定无缝和基础交叉淡化”的阶段安排。

- 用户最新意见：交叉期间暂停时，旧歌曲直接停止，新歌曲暂停；恢复只恢复新歌曲，不恢复交叉。此前“冻结两路并恢复剩余交叉”的建议已否决。其余交叉期间操作建议未确认，暂不继续讨论。
- 交叉淡化默认关闭，由用户独立开启。启用后用于自然进入另一首歌；手动切歌仍采用短淡出淡入，单曲循环及同曲目自循环不交叉叠加。
- 下一首准备不足、内容或输出路径不支持混音时，本次不交叉淡化，按普通衔接处理；不为等待效果而卡住当前歌曲、重播或跳过下一首。普通衔接时若下一首仍未就绪，遵循已确认的安静加载规则。
- AI 智能衔接作为交叉淡化的可选增强，默认关闭，在后台提前分析，只调整衔接时机、长度和曲线，不自行改选歌曲或调整队列。
- AI 分析尚未完成、失败或超出资源预算时，回退普通交叉淡化；连普通交叉淡化也不适用时回退普通衔接。实时播放不得等待推理。
- 智能分析默认在本地执行并缓存结果；未经用户明确授权，不上传音频或分析特征到云端。

### 已确认但随交叉功能暂缓的 A/B 视觉交接

- B 实际开始播放时交接当前歌曲归属，标题、时间轴、队列与系统媒体信息对应 B；随机队列换位与待播放意图消费在此交接点发生。
- 保留现有封面、文字、歌词等元素的短过渡手感，不把视觉过渡拉长到音频交叉淡化的时长；A 可作为非交互的退出画面短暂保留。
- B 开始播放后，歌词和进度必须对应 B 的实际播放位置与时长；不混用 A 的尾部时间。视觉平滑不能成为错误的 B 歌词时间。
- 允许提前准备 B 的封面、歌词和颜色，但不提前改变当前展示；资源迟到不阻塞音频交接，旧内容作为过渡保留，新资源就绪后接替。
- 此处的双曲目交接方案随交叉功能暂缓。普通切歌仍需保留现有元素短过渡、歌词与时间正确归属、资源迟到不阻塞音频等已确认体验。

## 播放页元素过渡分析

以下为提交与当前代码的分析，具体实现机制仍可重构。普通切歌体验继续保留；涉及双曲目交叉的建议随交叉功能暂缓。

- `0fe6b2e0` 与 `c558d8b2`：封面切歌时不先清空旧图，加载失败也保留已有图；封面请求身份为来源、歌曲 ID 与内容代次，普通元数据补丁不重新请求或打断动画。`BlurBackground.kt` 部分旧注释仍写失败置空，与最终执行逻辑不符，应以代码与修复提交为准。
- 手机封面在新位图就绪后执行约 500ms 淡入，旧图保留至新图进入完成，新旧图配合模糊变化。慢加载时旧图附加模糊与白色遮罩，快加载不闪加载提示。此效果由图片就绪驱动，现阶段不受音频混音比例驱动。
- 平板 `PadNowPlayingPanel.kt` 封面以请求模型变化驱动约 500ms 过渡，内部再异步加载图片；触发时机与手机等待位图就绪的路径不同，不能假设已经统一。
- `PlayingHeader.kt` 标题与副标题分别采用约 400ms 和 450ms 的水平滑动及先出后入淡化；目标是文字值而非整个歌曲对象，同文案不会仅因换曲而重播文字动画。
- `LyricLayout.kt` 按歌词文档整页模糊和淡入淡出，退出页冻结显示时间，新页只在身份与时间匹配时跟随。轻量模式为先淡出再淡入，不做整页模糊。歌词暂未就绪时保留旧文档；空歌词变为有内容也触发文档更新。
- `3249875f` 关闭全局主题颜色逐帧动画，保留局部背景颜色过渡与绘制期动画，避免每帧推动整页重组。
- `45ca0876`：队列滚动需要区分主动点选与自动或按钮步进，结合可见项决定是否回顶；不能仅凭新旧列表顺序猜测用户意图。自然交叉应作为自动推进，不应强制打断用户浏览位置。
- B 的时间轴必须使用 B 的实际播放位置与时长；不把 A 的尾部时间作为 B 歌词的输入，也不混合 A/B 的播放时间。进度条形状可保持平滑，但不能让视觉插值成为错误的 B 歌词时间。
- B 资源未就绪不阻塞音频交接：封面暂留旧图，歌词旧页冻结且不可误操作；资源就绪后接替。旧图长期保留是否应标识为沿用背景，以及歌词加载提示的具体效果，仍待确认。

## lmedia 当前行为分析（2026-10-26，待用户判断）

本节记录源码现状，不自动升级为重构需求。阅读了来源状态、绑定入库、内容解析、各类来源、WebDAV 缓存与元数据补全、队列元数据刷新，以及相关测试和近期提交。未运行多端应用验证；平台输出、已打开流的中断效果不能仅由 lmedia 静态代码保证。

### 来源生命周期与媒体库

1. 各来源独立初始化、扫描、发布结果及入库；播放只等待目标来源，不等待所有来源扫描完。数据库事务仍共用数据库。
2. 来源的扫描状态、最后成功结果、内容读取就绪状态、数据库提交状态分别记录。扫描失败与数据库写入失败是不同错误；入库失败可以重新提交最近成功结果，不必重新扫描。
3. 已就绪来源通常在普通刷新期间保留读取能力；刷新失败或取消保留上次成功结果。首次连接、换配置、清除认证和停用等不能一概按普通刷新处理。Subsonic 的 retry 会重连，refresh 才保留已有就绪能力。
4. 同一来源扫描忙时重复刷新通常直接忽略；任务代次防止取消后的迟到结果发布。
5. 完整扫描成功后按来源对账：更新现有歌曲、加入新歌曲，缺失歌曲标记不可用，默认保留记录及原分类关系。自动清理不可播放元素默认关闭；开启后成功同步或停用会触发清理，也可以手动清理。
6. 停用先持久化开关，阻止后续提交，停掉来源任务并标记数据库歌曲不可用。重新启用重新初始化。没有在绑定仓库中直接暂停播放器或移除播放队列的逻辑；不能承诺已打开的播放流一定立即停止或一定继续。
7. 来源不存在或被停用时拒绝新的音频解析；尚未就绪默认最多等待 15 秒，明确不可用则立即失败。这里的 15 秒是来源就绪等待，不是完整下载或播放总超时。
8. 封面可在有限等待失败后仍尝试读取，以支持本地快速显示；歌词等待来源就绪或明确不可用，当前没有与音频相同的默认 15 秒超时。

### 元数据变化与播放队列

9. 队列按来源和歌曲身份从数据库更新标题、时长等对象信息，使用 Sync 更新保留当前歌曲与顺序；数据库暂时查不到的项仍保留，不因为其他来源先完成而截断队列。
10. 因此，数据库清理、来源停用、扫描缺失不等于从当前队列删除该项。已经存在于队列中的不可用项能否继续发声，还涉及播放器和已打开的媒体资源。
11. WebDAV 单曲标签补丁只更新该歌曲及分类关系，不把其他歌曲标为失效。补丁错误单独报告，不覆盖完整扫描入库状态。封面普通元数据补丁不重启请求的近期修复继续适用。

### 本地来源与文件管理

12. Android MediaStore 在权限允许时读取系统媒体库，监听媒体库变化触发刷新，并支持最短时长筛选；权限不足显示来源不可用。目录来源扫描选定目录，识别音频并读取标签；不能假设所有平台都有系统媒体库的实时监听。
13. 沙盒导入将文件复制到应用管理目录，校验音频并根据已有路径或内容摘要识别重复，失败尝试回滚临时文件和索引。
14. 沙盒重命名保留稳定歌曲 ID；同名目标已存在则失败。删除采用暂存、确认更新、再完成删除的流程，失败具备恢复路径。沙盒删除文件与仅从播放队列移除是不同操作。

### WebDAV 列表与渐进补全

15. 首次扫描以目录遍历和文件命名生成列表，不要求先下载整库；记录文件大小、指纹、同目录封面和同名歌词文件。歌曲 ID 由服务器地址与路径生成，重复返回的条目会去重。
16. 根目录访问失败使整次扫描失败，保留旧结果；单个子目录失败则跳过并继续发布扫描结果。后者仍被当作完整快照入库，因此失败子目录内的旧歌可能被标为不可用；自动清理开启时可能进一步清理记录。这是需判断的现状边界。
17. 缓存达到约 1 MB、30%、完整文件时分阶段尝试提取。已有有效标签时不重复做相同的部分提取；完整文件阶段补全可靠时长等信息。具体节点以 WebDavExtraction.kt 为准，部分旧注释仍只写 30% / 100%。
18. 封面优先同目录独立图片，再用已提取的内嵌封面；歌词优先同名 .lrc，再尝试本地缓存文件的内嵌歌词。边车内容会本地缓存；完整内嵌内容能否取得受下载与提取进度影响。
19. “后台下载补全”和“远端元数据同步”是独立开关，默认均关闭。后台补全逐曲下载尚无完整元数据的歌曲；同步可上传本地提取结果、拉取其他设备已有结果，只读目录等错误单独显示，不把整个来源置为扫描失败。
20. 后台补全和同步默认只允许 Wi-Fi / 以太网；移动、其他及未知网络暂停。允许用户本次手动继续，网络类型变化后重新判断；已缓存内容保留。主动播放请求不受这项后台网络限制。这不是按播放队列准备下一首的功能。

### 缓存与现有边界

21. 通用 HTTP(S) 播放地址可以改写为本机缓存代理地址，边读取边缓存；不支持本地缓存的通用路径可退回原始地址。WebDAV 本身在无缓存目录的平台直接声明不支持。
22. 当前缓存是连续文件前缀，缺少的部分从前缀末尾继续下载。播放器可以请求 Range，但跳到尚未缓存的远处不等于已有稀疏分段缓存能力，可能需要先补齐中间内容。
23. WebDAV 缓冲显示使用已缓存字节占比，包含此前播放和后台补全留下的缓存；它不是精确的音频时间映射。本地来源不显示在线缓冲条。
24. 缓存共享配额，由 WebDAV 设置提供上限，默认 2 GiB，按 LRU 淘汰；当前注册的播放文件受保护，暂停时也保留保护。已实现的缓存不能直接当作独立的用户永久下载管理。
25. 有缓存不等于完整离线播放链路：音频解析先检查来源就绪，再进入缓存改写；冷启动断网、来源连接失败时，完整缓存也可能无法从正常入口播放。普通刷新失败保留 Ready 与冷启动连接失败是两种情况。

## lmedia 最新确认与讨论收敛（2026-10-26）

- WebDAV 子目录扫描失败的具体处理属于来源内部实现，由实现方根据可靠性选择方案，不再要求用户确认每个分支。基础来源协议应明确区分完整结果、部分结果与失败，避免不完整扫描误删已有内容；这是实现方向，不要求沿用现有状态结构。
- 停用来源：当前不考虑停止正在播放的歌曲元素，确保库里的歌曲能够正常移除即可。不将“移除库内歌曲”扩展为必须立即停止当前播放或删除队列项；物理清理、可恢复记录等存储细节留给方案设计。
- 建立可供不同来源复用的通用缓存能力，覆盖歌曲列表、元数据及音频内容。启动时利用已有缓存尽快提供可用内容，后台刷新；不应仅因为远端来源尚未连接成功就阻止访问有效的完整本地音频缓存。缓存身份、有效性、更新与失效策略由架构方案提出。
- 音频缓存支持按定位目标读取和缓存：拖动到哪里，就从该位置所需的数据开始获取，不要求先补齐此前所有字节。具体范围请求与解码对齐由实现处理。
- 缓存存储可分段，但播放页不展示零散缓存段。缓冲条表达当前播放位置之后连续可播放的范围，不使用整首累计缓存字节比例。后续分析与实现参考 ExoPlayer 的缓冲行为，不能将底层缓存范围和播放器可播放时间范围混为一谈。
- 用户已感到逐项确认疲劳：本轮需求确认收束，已有约定足以进入架构分析。一般实现细节由实现方决定并验证；页面入口差异在处理对应页面时再讨论，交叉淡化、AI 和高级输出能力继续按既定范围暂缓或分期。
- 后续仅在存在影响使用体验、无法由已有约定推导的关键取舍时集中提出问题，不继续扩展逐条确认清单。未明确确认的现状不自动写成已确认需求。
